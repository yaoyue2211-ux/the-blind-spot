# THE BLIND SPOT

一款移动端优先的情境式自我观察网页 MVP。用户逐题回答日常情境，查看基于实际答案生成的全部维度观察和综合摘要。

## 本地预览

这是一个不需要安装依赖的静态网页。直接打开 `index.html`，或在项目目录运行任意静态文件服务器后访问本地地址。页面使用原生 HTML、CSS 和 JavaScript 模块。

## 项目结构

```text
index.html          页面入口
styles.css          深色移动端视觉样式
src/questions.js    情境题库与选项分值
src/scoring.js      汇总、排序和谨慎措辞
src/illustrations.js 页面情境插画（内嵌 SVG）
src/app.js          页面状态、逐题交互和报告渲染
README.md           使用与迭代说明
```

### 维护题目与评分

- 在 `src/questions.js` 添加或修改题目。`dimension` 必须使用 `src/scoring.js` 中已有的维度键。
- 每题建议保持三个清楚、互斥程度尽量高的选项；`score` 使用 0、1、2，代表本次回答中相关信号较少、有限、较明显，不表示正确与否。
- 在 `src/scoring.js` 修改维度名称、排序和报告措辞。不要把分数包装成操纵概率、诊断或对他人的确定预测。
- 在 `src/app.js` 修改页面内容与交互；在 `styles.css` 修改视觉样式。

## 隐私与产品边界

当前页面没有账号、服务器、数据库或支付功能。答案和可选补充只存在于浏览器当前页面内；刷新页面会清空。不要让用户输入姓名、联系方式、账户信息或其他敏感信息。正式上线前需要单独设计隐私说明、数据处理和支付流程。

报告把“事实观察”（用户选择及补充）、“谨慎假设”（可能值得进一步检查的情境模式）和“证据边界”（假设情境不是现实行为）分开呈现。分值不是心理诊断，也不用于推断真实操纵风险概率。

## 用 GitHub 保存与回退

1. 在 GitHub 新建一个空仓库。仓库可以先设为 Private。
2. 在本地项目目录初始化 Git，将文件提交为一个清晰版本，例如 `v1: first mobile MVP`。
3. 把本地仓库连接到 GitHub 仓库并推送。之后每次修改前先提交一个已知可用版本，再继续迭代。
4. 如果改坏了，在 GitHub 仓库的 **History** 找到上一个提交；可以查看差异或使用 GitHub Desktop 的 **Revert changes in commit** 生成一次反向提交。也可以切回某个历史提交检查旧版本，再从正确版本继续。
5. 不要把访问令牌、密钥或用户数据提交到仓库。

## 部署到 GitHub Pages

在仓库 **Settings → Pages** 中，选择从部署分支发布，分支选 `main`、目录选 `/ (root)`，保存后等待 GitHub 提供站点地址。每次推送到所选分支后，Pages 会更新站点。部署前用手机宽度检查题目、按钮和报告布局；更新后可用该地址分享。

## 第一版的范围

- 16 道情境题，逐题作答、显示进度、返回修改和跳题。
- 报告展示所有有回答支撑的观察维度与综合摘要，不含付费入口。
- 不保存或上传答案；刷新后清空。
- 页面插画由本地 SVG 绘制，不依赖外部图片服务；后续可继续替换成自有插画。
- 后续可以继续迭代题目表达、插画和报告解释。
